# AI-Native Engineering Journey

My personal engineering development system: a public record of what I study, build, break and fix on the way to becoming a Senior/Staff-level AI engineer.

It is meant to grow into three things:
- a **technical knowledge base** I can search and revisit
- a **teaching resource** that explains concepts in my own words
- a **portfolio** that shows real engineering progress over time

## Structure

| Folder | Purpose |
|---|---|
| `01-javascript/` | Core JavaScript: language fundamentals, async, tooling |
| `02-typescript/` | Type system, patterns, strict-mode practice |
| `03-software-engineering/` | Testing, Git, code review, clean code, CI/CD |
| `04-react/` | Components, hooks, state, performance |
| `05-nextjs/` | App Router, server components, routing, deployment |
| `06-nodejs/` | APIs, servers, auth, background jobs |
| `07-databases/` | SQL, Postgres, modelling, indexing, ORMs |
| `08-python/` | Python fundamentals, FastAPI, data and AI tooling |
| `09-llm-engineering/` | Prompting, evals, structured output, tool use |
| `10-rag/` | Embeddings, vector search, chunking, retrieval quality |
| `11-ai-agents/` | Agent loops, orchestration, memory, guardrails |
| `12-cloud/` | Hosting, containers, observability, cost |
| `13-system-design/` | Scalability, trade-offs, design write-ups |
| `projects/` | Things I build end to end |
| `notes/` | Quick notes, snippets, things I looked up |
| `architecture/` | Diagrams and decision records (ADRs) |
| `weekly-reviews/` | One review per week, using the template |

## Weekly habit

Every week, copy `weekly-reviews/TEMPLATE.md` to `weekly-reviews/YYYY-Www.md` and answer:

1. What I studied
2. What I understood
3. What I struggled with
4. What I built
5. What went wrong
6. How I fixed it
7. What I would do differently
8. What I can now teach someone else

## Conventions

- One folder per topic, one markdown file per concept or exercise.
- Code lives next to the notes that explain it.
- Prefer small, working examples over long theory.
- Commit often; the history is part of the portfolio.
